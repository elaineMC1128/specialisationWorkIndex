Operational Guidance

This project's target audience is toddlers with limited language and comprehension skills, so the interface aims to communicate its main functions through clear visual information rather than written instructions. Even when the interface follows this principle of approachability, some users may still need help understanding keyboard control and key operation. This area tests whether operational guidance is actually necessary, and if so, when it should appear and how strongly it should intervene.

Prototype 1: No Guidance (Baseline)

This version follows the visual conventions common in toddler musical toys, with no onboarding, tutorial pop-up, or instructional text. It serves as the control condition. Testing it first shows what a child can already understand through the interface's own visual language, and gives the later prototypes a clear standard to be measured against.

Prototype 2: Proactive Guidance

A short instruction appears automatically the first time each new screen is entered. This responds to children who may need guidance to take a first step with an unfamiliar object, rather than trying it on their own. This prototype tests whether that guidance reduces the confusion or hesitation seen in the baseline. Each instruction includes a skip option, which lets the same test also show whether automatic guidance interrupts a child's curiosity or limits their freedom to explore.

Prototype 3: On-Demand Guidance

This prototype shares its interface with the baseline, but adds a help button on every screen. The guidance content matches Proactive Guidance, though it only appears when a child or accompanying adult chooses to open it. Rather than enforcing a guided step, this version treats guidance as an optional resource, testing whether its presence alone is enough to help a child who gets stuck, without affecting the experience of a child who does not need it.

Randomised Visual Feedback

This project aims to let children clearly feel the causal link between their own actions and the instrument's sound and visual response. The sound design is already settled: the eight-key scale keeps the tone simple and stable, and removing Assisted Play gives children real room to explore and make mistakes. This shifts the open design question toward the visual layer. Can visual feedback with an element of randomness add playfulness and support open exploration, without weakening a child's sense that their own action caused what they see?

These three prototypes test different strengths of connection between a keypress and its visual response, along with different degrees of visual expressiveness. Learning Mode's visual feedback serves a different, functional purpose, indicating whether a note is correct, so it falls outside this area and is not tested here.

Prototype 1: Dynamic Light Bar

Each key has a fixed colour. Pressing it sends a column of pixel blocks in that colour rising above the key, and the blocks disappear when the key is released. This resembles an audio waveform, one of the most c ommon and direct ways to visualise sound. Because the effect stays close to its key, the connection between input and response remains clear. The varying motion adds novelty to repeated notes without breaking that connection.

Prototype 2: Pixel Pattern Canvas

This prototype extends the feedback area from the space above each key to the full screen. The colour of each generated pattern still matches its key, but its shape, position, size and orientation are randomised across the whole canvas. This adds visual richness and keeps a traceable link through colour, while testing what happens once the response is no longer tied to a fixed position.

Prototype 3: Reactive Pixel Animal

This prototype takes a bolder approach. Instead of generating a shape for each keypress, a pixel animal is already shown on screen before any interaction begins, and a keypress is answered through the animal's movement or change rather than a new image appearing. This draws on the way many toddler toys use animal characters to hold attention, and leaves more room for playful, expressive reactions. It also removes the spatial and colour link between action and response, leaving only timing to connect them. This prototype marks the boundary condition in the set, used to explore how far the connection between action and feedback can be loosened before it becomes unclear.
